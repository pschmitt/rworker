Usage: __ME__ ssh [--wait [SECONDS]] [-l USER | USER@] [-i FILE]NAME [SSH_ARGS...]
       __ME__ ssh --create [--rm] [-l USER] [UP_OPTIONS]

SSH to a worker over NetBird with its pinned host key. Everything after the
name goes to ssh, so options and a command both work.

--wait keeps trying until the worker accepts SSH; optional SECONDS sets a timeout.
Without a timeout, interrupt it with Ctrl-C.
It also works immediately after NAME. The remote command runs only once.

Default user: agent on ad-hoc workers this host created and on pool workers,
yourself on other owners' ad-hoc workers (RWORKER_USER overrides). Workers
this host does not know yet are looked up on the control host.

-i FILE (--identity FILE) logs in with that private key only, as ssh -i with
IdentitiesOnly does; it applies to existing workers, not to --create.

--create makes a new worker and logs in, like `up --ssh`; up's options
(--ttl, --flavor, --disk, --profile, --arch, --queue-timeout, --scratch, --topic) go with it, in any order. -l USER picks the
login user, as with ssh (agent by default on a new worker). --rm deletes the
new worker when SSH exits, including after an unsuccessful login.
The session shows up as an `ssh` job with the worker's topic, like exec's
job, and is recorded in the job's log where the worker has script(1).

Examples:
  __ME__ ssh --create --ttl 4h
  __ME__ ssh --create --rm --profile gh-aarch64
  __ME__ ssh --create --rm --profile gl-x86_64
  __ME__ ssh adhoc-1234abcd
  __ME__ ssh pschmitt@adhoc-1234abcd sudo journalctl -b
  __ME__ ssh -i ~/.ssh/id_ed25519_build adhoc-1234abcd
  __ME__ ssh --create -l pschmitt
  __ME__ ssh adhoc-1234abcd -L 8080:localhost:8080
  __ME__ ssh adhoc-1234abcd 'cd src && nix develop -c cargo build'
