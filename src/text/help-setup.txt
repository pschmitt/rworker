Usage: __ME__ setup TOPIC [NAME] [OPTIONS]

Get an ad-hoc worker ready for a kind of work, using this host's own
settings. Everything is on by default; flags switch parts off.

Topics:
  nix                configure the S3 cache and access tokens for private inputs
  nix cache          configure only the S3 cache
  nix auth           configure only private-input access tokens
  nix builder        print a Nix builders line for a worker or the gateway
  nix upload-blob    import local files into the worker’s Nix store
  nix-cache          alias for nix cache
  nix-builder        alias for nix builder
  niks3-token        reissue the worker's short-lived cache push token
  register-log-file  make an existing log available as a job
  netbird            start or restart NetBird on an existing CI worker
  tailscale          start or restart Tailscale on an existing CI worker

  __ME__ setup netbird WORKER
  __ME__ setup tailscale WORKER

Start or re-enroll the selected mesh provider on an active GitHub Actions
or GitLab prebuilt-image worker. The controller must allow the provider
for that profile. The command prints a SOCKS proxy URL for use on the
worker. The SSH relay stays available throughout setup.

  __ME__ setup register-log-file WORKER JOB --log PATH

Use an absolute path to an existing file on the worker. View it with
`logs WORKER JOB`. Registration leaves the process that writes the log alone.

  __ME__ setup niks3-token NAME [--force]

The controller installs a fresh token in /run/rworker-niks3 on the worker
for the rest of its lifetime. The worker can use `niks3 push /nix/store/...`
and write `rworker-*` pins. Use this after opting out or to retry a failed
install. `up` issues the token by default, and `extend` renews it.
Workers whose images lack /run/rworker-niks3 are skipped.

  --force          reissue the niks3 token of someone else's worker

  __ME__ setup nix NAME [--no-cache] [--no-auth] [--auth-host HOST]... [--dry-run]

Over SSH (pinned host key), never through the OpenStack metadata service and
never via the control host, `setup nix` pushes into /run/rworker-nix on the
worker (tmpfs, agent-owned, 0700, gone with the worker):
  cache  this host's s3:// substituters, the trusted public keys and the AWS
         profile each s3:// URL names (profile=...), read from
         $RWORKER_AWS_CREDENTIALS_FILE, $AWS_SHARED_CREDENTIALS_FILE or
         ~/.aws/credentials. The worker then substitutes from the private
         cache.
  auth   this host's `access-tokens` (as `nix config show` reports them), so
         the worker fetches private flake inputs itself. A build that
         evaluates on the worker then needs no upload of inputs from here.
Nothing else of nix.conf is copied (it can hold netrc paths); non-S3 caches
are not reachable from OpenStack anyway.

  --no-cache       leave out the cache part
  --no-auth        leave out the access-tokens
  --auth-host H    push only the token for host H (repeatable), e.g.
                   github.com; default: every token this host's Nix has
  --dry-run, -n    show the substituters, profile names and the hosts whose
                   token would be pushed; push nothing (credentials and
                   tokens are never printed)

up and exec do both by default, as far as this host has something to give
(--no-nix-cache, --no-nix-auth to leave one out).

  __ME__ setup nix cache NAME [--dry-run]
  __ME__ setup nix auth NAME [--auth-host H]... [--dry-run]

Use `setup nix -- NAME` for a worker whose name matches a Nix subcommand.

Use read-only credentials only: anyone with a shell on the worker (the agent
user) can read what you push, tokens included. Run it again after rotating a
key or token. A worker whose image predates this (no /run/rworker-nix) gets
nothing; the command says so and fails. For builds through --builders, also
set builders-use-substitutes on this host, or this host fetches the inputs
itself and copies them over instead of letting the worker substitute.

  __ME__ setup nix builder NAME [--json]
  __ME__ setup nix builder [--profile NAME | --arch ARCH | --pool NAME] [options]

With NAME, print a Nix builders line for that worker, e.g.:
  nix build --max-jobs 0 --builders "$(__ME__ setup nix builder NAME)" .#pkg
For hosted workers, use --json. The result includes ssh_config for the
worker's pinned relay connection. Prepend it to the client's SSH config.

Without NAME, print a line for the on-demand builder gateway: the first
build leases a worker, later builds share it, and it goes away when idle.
The selector picks the worker the gateway leases (sent as Nix's
remote-program); without one the gateway uses its default profile:
  --profile NAME   a worker of this profile (gh-aarch64 leases a GitHub runner)
  --arch ARCH      a worker for this architecture (x86_64, aarch64); falls
                   back to a GitHub runner when no profile matches
  --pool NAME      a fresh ad-hoc worker from the profile this pool uses
  --gateway HOST   gateway host (RWORKER_BUILDER_HOST, default: control host)
  --identity, -i FILE
                   private key of the local Nix daemon for the gateway
                   (RWORKER_BUILDER_IDENTITY, default -: the daemon's own)
  --host-key KEY   base64 public host key line (RWORKER_BUILDER_HOST_KEY,
                   default: looked up in your known_hosts)
  --system SYSTEM  system of the entry (default from the selector)
  --jobs N         builds Nix runs at once on the entry
  --features LIST  comma-separated system features, - for none

  nix build --max-jobs 0 --builders "$(__ME__ setup nix builder --arch aarch64)" .#pkg

  __ME__ setup nix upload-blob NAME [--name STORE_NAME] [--] FILE...

Upload regular files over pinned SSH and import them with flat SHA-256.
The store name defaults to the local basename. Use --name with one file
to match a package's required filename. Prints one store path per file
(or a JSON object with a paths array). Imported paths are subject to the
worker's normal Nix garbage collection.
